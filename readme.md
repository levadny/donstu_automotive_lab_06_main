### Шаг 1: Создание проекта в MATLAB

Есть три основных способа создать проект, в зависимости от того, с чего вы начинаете.

**Способ А: Из существующей папки (самый частый для вашей задачи)**
Этот способ идеален, когда у вас уже есть папка с кодом, моделями и, возможно, Git-субмодулями (субпроектами MATLAB).

1.  В MATLAB на вкладке **Home** выберите **New > Project > From Folder**.
2.  Укажите папку, которую нужно превратить в проект (это будет корень проекта).
3.  MATLAB предложит настроить проект:
    *   **1**: Выберите папки, которые нужно добавить в **Project Path**. Это критически важно, чтобы MATLAB видел ваши функции и модели. Обычно сюда добавляют корень проекта и все подпапки с кодом, но сюда не нужно добавлять папки содержащие субмодули гит (и/или субпроекты MATLAB).
    *   **2**: Укажите **Startup** и **Shutdown** файлы (опционально). Это скрипты, которые будут выполняться при открытии/закрытии проекта. Например, можно настроить переменные окружения.
4.  Нажмите **Finish**. MATLAB автоматически добавит все файлы из папки в проект.

**Способ Б: Создать «пустой» проект вручную**

1.  Выберите **New > Project > Blank Project**.
2.  Укажите папку. Проект будет пустым.
3.  Вручную добавьте файлы: на вкладке **Project** в галерее **Tools** нажмите **Add Files** или просто перетащите файлы в панель **Project Files**.

**Способ В: Клонировать из Git (если репозиторий уже есть)**
1.  **Home > New > Git Clone**.
2.  Укажите URL репозитория. После клонирования создайте проект из полученной папки (Способ А).

### Шаг 2: Подключение субпроекта MATLAB как Referenced Project

Это ключевой момент для организации модульной архитектуры в современной automotive-разработке, где на одном уровне идут субпроекты MATLAB и субмодули git.

**Важное условие:** У проекта, который вы хотите подключить, **должен быть свой .prj-файл**. Если у вашего субмодуля (библиотеки) его нет, сначала создайте проект внутри него по инструкции выше - как для полноценного проекта MATLAB.

**Процедура добавления ссылки:**

1.  Откройте **родительский проект** (главное приложение).
2.  На вкладке **Project** в секции **Environment** нажмите кнопку **References** .
3.  В открывшемся окне нажмите **New Reference**.
4.  **Выберите тип ссылки — это критично для избежания дублей:**
    *   **Relative (Относительный)**: Выбирайте этот тип **всегда**, если проект-компонент находится внутри папки родительского проекта (например, как Git-субмодуль в `libs/`). Это гарантирует, что при клонировании репозитория у коллег ссылка не сломается.
    *   **Absolute (Абсолютный)**: Только если проект лежит на сетевом диске или в фиксированном месте, не связанном с родительским проектом - по факту это большая редкость и не используется в разработке.
5.  Укажите путь к .prj-файлу проекта-компонента и нажмите **Add**.

**Что произойдет после добавления:**
*   MATLAB добавит пути из проекта-компонента в свой search path при загрузке.
*   **MATLAB всегда загружает referenced-проекты до загрузки родительского проекта.** Это позволяет родительскому проекту использовать функции из компонента в своих startup-скриптах.

### Шаг 3: Как избежать дублирования

Проблема с дублированием возникает, когда вы пытаетесь подключить один и тот же субмодуль в нескольких местах иерархии: например в корне основного проекта и в субмодуле, который представляет собой субпроект.

**Правильная архитектура:**

Предположим, у вас есть:
*   Библиотека **A** (базовая)
*   Библиотеки **C** и **D**, которые зависят от **A**
*   Главное приложение, которое зависит от **C** и **D**

**Неправильно (будет дублирование):**
*   Вы клонируете **A** внутри **C**, и еще раз клонируете **A** внутри **D**. Тогда в главном приложении будет две копии **A** (по одной в `C` и `D`).

**Правильно (рекомендация MathWorks и разработчиков одной большой и крупной европейской automotive-компании):**
1.  Храните **A** как **отдельный Git-репозиторий**.
2.  В главном проекте добавьте **A** как **Git Submodule** в какую-то папку (например, `libs/A`).
3.  **НЕ добавляйте** копии **A** внутрь репозиториев **C** и **D**.
4.  В проектах **C** и **D** добавьте **A** как **Referenced Project**, указав **Relative** путь к `libs/A/A.prj` (относительно корня главного проекта, если структура папок это позволяет, или относительно корня самого C/D).
5.  В главном проекте добавьте **C** и **D** как Referenced Projects.

**Результат:** В файловой системе существует **ровно одна копия** библиотеки **A** (в `libs/A`). MATLAB при загрузке главного проекта загрузит `A.prj`, `C.prj`, `D.prj`, но все они будут ссылаться на **один и тот же экземпляр** кода в `libs/A`. Дублирования не будет.

**Ключевое правило:** Никогда не делайте `git clone` одной и той же библиотеки в разные папки внутри одного проекта. Используйте **один экземпляр + множественные ссылки (References)**.

**Работа с test harness (MIL):** При тестировании компонента (модели), поступаем аналогично. Подтягиваем тестируемый модуль как субмодуль гит, библиотеку к тестируемому модулю грузим также как субмодуль гит на одном с модулем уровне, а в тестовый проект добавляем их как субпроекты MATLAB на одном уровне.

### Дополнительные возможности

**Просмотр и редактирование файлов компонента:**
В родительском проекте нажмите **References**, выберите проект в дереве, затем **Show Files**. Вы можете открывать и редактировать файлы компонента прямо оттуда, не переключаясь между проектами.

**Извлечение папки в отдельный проект:**
Если у вас уже есть папка внутри проекта, которую вы хотите сделать отдельным компонентом, нажмите на неё правой кнопкой в панели **Files** и выберите **Extract to Reference Project**. MATLAB создаст новый `.prj` и автоматически переделает ссылки.

**Изменения в R2025a:**
Начиная с R2025a, механизм **Checkpoints** для отслеживания изменений в referenced-проектах **удален**. Теперь для этих целей рекомендуется использовать **ТОЛЬКО** Git.
